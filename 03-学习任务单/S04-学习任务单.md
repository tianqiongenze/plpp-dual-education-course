## 知识建构精讲要点(理论 35min,教师主持)

### 共享包纪律(工程铁律①)
- ≥2 服务共用的能力必下沉 platform-common,禁止服务内复制
- 下沉什么:事件发布/Outbox、锁策略、鉴权过滤器、通用 DTO
### vendored jar 事故复盘
- 每服务目录独立 vendored .mvn/platform-common.jar(10-19 旧拷贝)
- 根目录/本地 m2 同步均无效——构建时用的是 vendored 那份
- 教训:公共包更新必须五份同步+构建验证,镜像内 class 指纹校验(BVV)
### 契约与版本
- 公共包=服务间'软契约':改签名=破坏契约,须全量同步+回归
- 事件 schema 同理:字段变更先查所有消费者

## 实训实施(70min,双师巡回)

1. **1. 盘点** — find 各服务 .mvn 下 platform-common.jar 的 md5,列五份指纹表
2. **2. 同步** — 用最新构建产物覆盖五份 vendored jar(教师演示,学生跟做)
3. **3. 构建验证** — 选 1 个服务 docker build,宿主侧解包校验关键 class 存在
4. **4. 复盘卡** — 把事故写进组内'事故库':现象→根因→修复→预防
