# 项目对接与同步机制(PLPP ⇄ 课程仓)

> 立项约定(用户指令):**凡 PLPP 项目再更新任何信息,相关内容同步到课程仓库的相应位置。**

## 1. 两个仓库

| 仓库 | 内容 | 地址 |
|---|---|---|
| PLPP(项目源) | 生产级平台代码+文档+运维报告 | `tianqiongenze/personalized-learning-platform-plus`(私有) |
| 课程仓(本仓) | 课程标准/授课计划/教学方案/任务单/PPT/学生资料 | `tianqiongenze/plpp-dual-education-course`(私有) |

## 2. 同步什么、到哪去

| PLPP 变更 | 课程仓落点 | 动作 |
|---|---|---|
| 文档(PROGRESS/审计/报告/运维手册) | `project-references/` | 复制快照(带日期子目录) |
| 新事故/新根因 | `04-双元制实施方案.md` §5 事故表;对应课次情境 | 人工更新+生成器重渲染 |
| 新修复/新代码路径 | 对应课次任务单实训步骤 | 人工更新+重渲染 |
| 新接口/NodePort/环境变化 | 任务单命令、`学生手册` §6 | 人工更新 |
| 版本演进 | 各文档头部"基准阶段"标注 | 对齐 PROGRESS 阶段号 |

## 3. 同步脚本

`tools/sync-from-plpp.sh`(本仓 tools/ 下):
```bash
./tools/sync-from-plpp.sh <PLPP仓库本地路径>
# 动作: 拷贝 PROGRESS.md/docs 关键报告 → project-references/<date>/,
#       输出 diff 摘要提示哪些课次材料需要人工复核
```

## 4. 同步节奏

1. **事件驱动**(主):PLPP 每次有 commit/事故/数据变化,执行同步脚本→人工复核"需复核"清单→重渲染受影响课次(`python tools/generate.py` 全量重渲染,幂等);
2. **每周例行**:周五课程备课检查点,即使项目无变化也确认一次基准阶段号;
3. **学期版本**:学期结束打 tag(如 `v2026-spring`),课程资料定版。
