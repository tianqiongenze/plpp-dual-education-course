# 双元制实施方案(校企双主体育人手册)

> 依据《课程标准》§4 细化。本文件是学校教师、企业导师、实训管理员三方共同遵守的执行手册。

## 1. 双元育人组织架构

```
        ┌──────────────────────────────────────┐
        │      课程负责人(教授级高工/双师)        │
        └──────┬───────────────────┬───────────┘
       校内教师团队(师傅)        企业导师团队(Meister)
       · 理论+实训主导            · 每周工程师时间 30min
       · 过程评价 75%             · 代码评审/事故复盘
       · 六步法主持               · 企业导师评价 25%
               └───────┬───────────┘
                  学徒组(4人/组 × N组)
        角色轮换:工单员/操作员/检查员/费曼员
```

## 2. 学期双元日历(16 周对照)

| 周 | 校内(教师元) | 企业(工程师元) |

| 2 | 需求工程实训 | 工程师时间②:申报书怎么写→怎么核对(虚标案例) |
| 3-4 | 架构与公共包 | 工程师时间③:代码评审入门(PR 规范) |
| 5 | IAM 与安全 | **M1 评审会(工程师任第二评委)** |
| 6-7 | 数据中台 | 工程师时间④:数据库选型之争(TiDB vs CRDB) |
| 8-9 | 图谱与向量 | 工程师时间⑤:AI 检索产品化权衡 |
| 10-11 | 智能体 | 工程师时间⑥:LLM 成本与缓存(LCO 三层缓存) |

| 16 | 部署压测+答辩 | **M4 终审(企业工程师主评)** |

## 3. 学习站(Lernstation)设置

实训室设 4 类学习站,学生按六步法流转:
1. **S-A 文档站**:项目文档/审计报告/运维手册(只读终端)
2. **S-B 编码站**:每人一台开发机,学生分支开发
3. **S-C 集群站**:教学 K8s 租户(每组独立 namespace)
4. **S-D 白板站**:费曼讲台+架构图区(不允许带电脑,只允许白板笔)

## 4. 任务单契约制

- 每次课开始,工单员到"任务台"领取本组《学习任务单》(16 份,见 03-学习任务单);
- 任务单即契约:含**交付物清单+检查清单+评分点**;检查员逐项勾验;
- 未通过检查的学习情境,费曼员不得上台(倒逼实训质量)。

## 5. 事故即课程资源(双元制"故障教学法")

PLPP 真实事故是本课程最贵的教学资产,固定用作对应课次的导入情境:
| 事故 | 课次 | 教学价值 |
|---|---|---|
| _sync_meta 跨库炸(冒烟过、main 必炸) | S07 | 冒烟≠全路径验证;追踪真实执行路径 |
| vendored jar 陈旧(五服务拷贝) | S04 | 公共能力共享包纪律 |
| SerializationFailure 风暴 | S07/S15 | 分布式一致性;重试退避设计 |
| 磁盘压力→CRDB-a Pending→拒连 | S16 | 爆炸半径;容量水位监控 |
| 403 之谜(网关信任头) | S03 | 零信任;不要把安全设计当 bug |
| Prisma 迁移 600s 超时(litellm) | S10 | 诚实搁置:何时该绕行而非硬修 |
| 现象日志≠根因(Loki 误诊) | S15 | UIM:先正向验证再下结论 |

## 6. 企业导师工作规程

1. 工程师时间固定每周 X 时(线上),内容三选一:事故复盘 / 代码评审 / 职业素养;
2. M1/M3/M4 评审会到场,使用《里程碑评分矩阵》(见考核评价方案);
3. 对学生 PR 的评审意见限"四问":瓶颈在哪?容灾怎么做?扩缩容路径?成本权衡?
4. 企业导师评价表由课程负责人存档,占过程分 25%。
